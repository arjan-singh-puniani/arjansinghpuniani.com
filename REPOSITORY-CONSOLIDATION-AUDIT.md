## Preservation and recovery

Unique textual material is stored once under `archive/consolidation-20261017/objects/<sha256>.txt`; its original root/path/container, byte length, SHA-256 and Git blob identity are in `inventory.json`. Text extensions are deliberately inert so legacy application copies cannot enter compilation or lint discovery. These are recovery objects, not alternative active implementations. Original containers, binary evidence and unresolved cloud files have a separate local preservation home documented in the cleanup manifest.

Recover an archived source by locating its inventory row, copying the referenced object to the desired path, and verifying SHA-256 first. Never execute an old patcher against current source without inspecting its anchors and comparing current architecture. Previously committed variants can also be recovered using the recorded Git blob.
