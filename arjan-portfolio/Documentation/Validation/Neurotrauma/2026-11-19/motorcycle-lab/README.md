# Motorcycle mechanism lab

The user narrowed the next step to a detailed, deformable motorcycle that can be pulled apart. This implementation adds a standalone `/motorcycle-mechanism-lab/index.html` dashboard and a link from the existing neurotrauma project; the F1 explorer and fictional handoff remain intact.

## Asset and behavior

The lab uses Jacobdesigns' explicitly CC BY 4.0 **(FREE) Honda CRF 450** artist reconstruction. It is identified as a Honda throughout. Detailed DR650 candidates were paid or viewing-only, and simpler free generic assets were rendered and rejected. No purchase was made. The original creator's public API license, embedded asset credit and retained license file agree. The package came from a pinned public redistribution. `public/motorcycle-mechanism-lab/provenance.json` records source URLs, 12 file hashes and the native-render preview's hash/camera. Normal and metallic/roughness texture conversion was verified pixel-identical. The prepared model package is 11,271,179 bytes; the preview is 89,446 bytes. No npm dependency or external runtime service was added; the lab reuses the repository's MIT-licensed Three.js r186 and helpers.

The source's 81 surfaces and 49-joint rig become 83 editable surfaces in 15 authored assemblies, retaining 179,747 triangles. Two shared bodywork surfaces are separated by their source rig assignments so front and rear panels can move independently. Parent-child transforms preserve connected wheel/fork/handlebar relationships until release. Direct mouse/touch gestures and keyboard-accessible sliders support local mesh dents, connection release, settling, exploded inspection and restoration. Reset restores original vertex positions, authored normals and hierarchy. The camera was refined to use mesh samples, preserve both grips in the controls view, and keep the bike prominent. Environmental fog applies to the grid, while model materials remain legible when narrow-screen framing moves the camera back.

The scene record captures the latest 100 edits, relative time, assembly, input source/pointer type, contact point/normal and coordinate frame where available, authored deformation setting and final positions. It is generated locally with no patient fields or server transmission. The UI and model notes explicitly distinguish mesh edits and visual release settings from measured forces, material failure, crash reconstruction and clinical outcomes. There is no rider, injury, imaging or recovery predictor, no fracture-surface generation and no collision solver between assemblies.

The existing neurotrauma route remains 11.8 kB / 124 kB first-load JS. The six new unit tests cover source hierarchy classification, independent front/rear bodywork, a connected acyclic assembly tree, smooth bounded dent influence, bounded gesture velocity and a bounded motion timestep.

`tests/motorcycle.browser.mjs` passes against the optimized build in hardware-rendered Chrome at 1440×1000, 1024×768, 390×844 and 320×740. It verifies actual vertex deformation, independent rear bodywork, connected child movement, real hard mouse/touch pulls, release/settling, pointer cancellation, keyboard orbit and sliders, exact vertex/normal/hierarchy reset, finite geometry, full handlebar framing, downloads/provenance, no external runtime requests, no horizontal overflow and zero automated WCAG A/AA violations. WebKit at 390×844 renders the real model and passes deformation. No-JavaScript, blocked-model and disabled-WebGL scenarios retain a local preview and sources with disabled enhanced controls. The final static lighting/fallback refinements were covered by focused ESLint and a complete production-build browser rerun after full verification.

The existing toolkit browser suite also passes at five Chromium widths (1440, 1024, 768, 390, 320) and WebKit touch at 390: all direction/stage comparisons, keyboard/touch interaction, source/rationale disclosures, metadata, internal destinations including the new lab, no-JavaScript/blocked-image/blocked-viewer fallback, zero automated accessibility violations and the one-page A4 handoff. Results and the successful verify log are retained alongside selected screenshots. Screenshots of assembled, deformed, released, exploded, controls, narrow-screen and fallback states were opened and reviewed. Post-deployment evidence is recorded on the pull request.

Physical phones, human screen-reader sessions and calibrated structural/biomechanical validation were not performed. The deformation kernel, release travel, settling orientation and motion constants are authored visual behavior. An exact DR650 remains a separate asset-acquisition and assembly-preparation task.
