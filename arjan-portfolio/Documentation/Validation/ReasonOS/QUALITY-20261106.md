# ReasonOS quality review candidate - 2026-11-06

This iteration uses explicit software and human review gates. It does not assign a quality score or predict admissions outcomes.

## Defects fixed

- Recomputed evidence: the workspace plugin now derives duration, uncertainty and sample indices from source metadata, endpoints and calibration. Altered derived values, off-source coordinates, unconfirmed endpoints and unconfirmed image leads are rejected. Plugin provenance version is 1.1.0.
- One sample clock: readout, saved measurement and export use the recorded origin sample plus rounded endpoint offsets. The previous relative/absolute half-sample rounding disagreement has a regression case.
- Finite signals: a finite but extremely small WFDB gain can overflow the calibrated voltage. Those recordings are rejected.
- Complete dependencies: proposed interpretations must name every actual measurement input. An omitted dependency cannot bypass a later review flag.
- Original bytes: CSV and WFDB header identities hash original bytes, including a BOM. UTF-8 decoding is separate and strict. Public reference headers are also hashed before decoding.
- Intentional measurements: initial calipers are labeled preview guides. Both endpoints must be selected before saving. Image annotations require explicit lead/time-axis confirmation.
- Purposeful navigation: the Source/Measure/Reason/Review rail selects and focuses the relevant panel, with a mobile scroll action. The active step is exposed to assistive technology.
- Honest display limits: clipping is visible, gain can be reduced, and horizontal extent is explained. Fewer than twelve leads use a packed overview layout so a single V6 or other subset is not placed outside the view box.
- Composition and responsiveness: the focused strip precedes the twelve-lead overview. The desktop retains the overview; phone controls stay compact and use 16 px numeric/select text to avoid common mobile auto-zoom behavior. Reference overview paths are memoized so endpoint edits do not regenerate every lead path.

## Linked signal-origin explanation

The user's textbook screenshots identified an explanatory gap between waveform measurement and its physical source. New original SVGs connect the prescribed current dipole to an analytic potential field, electrode subtraction, amplifier and synthetic waveform. A tissue close-up distinguishes activation and recovery sequences, membrane voltage, ionic currents and equivalent source polarity. The explanation is visible in the case study, available at `/work/vector-ekg-reasonos/signal`, and opens inside the standalone workspace without discarding evidence. See `SIGNAL-ORIGIN.md` for all equations, units, assumptions, source context and reproduction commands.

Three rendered review passes produced substantive changes. Scientific review corrected reversed-input field metadata and an unsupported implication that a 55 mm display mask established a physical validity boundary. Visual review corrected the synthetic label, source-arrow identity, a tissue-label/meter overlap and inconsistent heading fonts, and added numerical dipole components. Phone/accessibility review replaced undersized SVG labels with contained scrolling diagrams, placed time/voltage feedback before the stacked views, and made the trace viewport follow user-selected time without animation. Final built-app desktop, tablet, phone and disclosure renders were captured across all three engines.

The final diagram harness passes linked source/lead calculations, unchanged source under input reversal, all four local boundary cases, keyboard scrubbing, local math rendering, no page overflow and preservation of workspace endpoints. Combined with the evidence-workspace/protocol harness, 30 inspected Axe states have zero violations (15 explanation/integration, 15 workspace/protocol). A diagnostic run against the live dev server was interrupted by a code-update navigation; production-build checks are the release evidence. Cross-engine transcendental rounding is checked to 1e-12 mV rather than strict bit equality. A workspace keyboard-selection assertion now waits for the actual React state transition rather than racing it.
