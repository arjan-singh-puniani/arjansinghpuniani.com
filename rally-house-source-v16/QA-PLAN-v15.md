# v15 verification matrix

## Evidence separation

1. Baseline: unchanged v14.1 compiled build, original tests, 600 real seconds unattended, recorded every ten seconds.
2. Agent-driven browser play: at least 1,200 real seconds, covering observation, catalog/floor placement, coaching, book, save/reload and viewport changes. Actions and screenshots are logged. This does not replace independent human testing.
3. Deterministic simulation: state extremes, distinct personalities, all six relationships, scarce resources, context-gated memories, event idempotency, favorites, weather and overnight recovery.
4. Final untouched observation: 600 real seconds with chronological causes, consequences and variety statistics.
5. Browser robustness: schema 6 migration, schema 7 round trip, partial activity reload, storage failures, corrupt/future saves, missing favorite objects, graphics recovery, portrait/landscape interaction and keyboard focus.

## Required assertions

- A low-energy actor scores rest above practice; equivalent needs yield character-specific alternatives.
- Confidence changes challenge utility. A low-confidence Mika may seek June; Leo can redirect toward equipment/practice.
- Company utility responds to social appetite and the actual partner relationship.
- Every state value remains finite and bounded across days; no offline depletion occurs.
- Busy participants and reserved resources cannot enter new scenes. Minor notices cannot interrupt a lesson or match.
- Repeated pair/family/place/motif loses weight. Strong warmth/rivalry or an unfinished salient consequence can outweigh a finite penalty.
- A memory-specific line cannot exist without the correct memory. An eyewitness claim requires a recorded witness.
- Near, attentive characters can witness events; distant or committed characters cannot. Replayed event IDs do not create extra consequences.
- Positive completed visits affect favorite selection, confidence/comfort and future destination utility. Moving retains identity; removal clears references.
- Culture and coaching identity change only on relevant completed actions or actual build changes, never menu selection.
- Possessions have one owner and one location. Interruption/reload cannot clone props or count unfinished use.
- Old walking tests remain. All schedule transitions become reachable without allowing shortcuts through the court or furniture.
- All new saved data survives serialization. Missing optional v14.1 state initializes safely. Invalid nested state fails before autosave.

## Human release gate (not fulfilled by automation)

Recruit independent players for watch/build/coach sessions. Ask them to name each person, describe an expected and surprising behavior, identify a favorite place, trace a witnessed event into a later action, and explain something their building changed. Ask whose absence they would notice. Record actual answers; do not infer attachment from scene counts.
